そのままメールに貼れる文面は[最後の章](#メール文面そのまま貼れる形)にある。

## IT にお願いする作業（2〜3分）

1. SharePoint 管理センター → **アプリ カタログ** → 「SharePoint 用アプリ」ライブラリを開く
2. `ctn-suite.sppkg` をアップロード（**既存のものを置き換える形。上書きで構わない**）
3. 表示される「**展開**」ダイアログで承認

すでに登録済みのため、今回は**更新**になる。アップロード後、一覧の「アプリのバージョン」が
**1.6.0.0** になっていれば成功。

## 登録後の作業（依頼者が実施。IT の対応は不要）

1. サイト コンテンツ → **`ctn-suite-client-side-solution`**（種類=アプリ）の「…」→ **更新**
   - サイト コンテンツに出る名前は `solution.name` である `ctn-suite-client-side-solution`。
     「CTN Suite」は Web パーツの表示名で別物
   - **「更新」はカタログに新しい版が登録されるまで出ない。** 出ていなければ IT の作業が
     未完了か反映待ち（数分〜30分待って再確認）
   - **「更新」が出ないことがある。** その場合はアプリを削除して追加し直す。
     **リストとデータは消えない**（REST プロビジョニングで作成しており、アプリの機能が
     作ったものではないため）。ただしページ上の Web パーツのプロパティは初期値に戻るので再設定する
2. ページを編集して Web パーツのプロパティを設定（データソース＝SharePoint リスト）し、
   **「変更の公開」**を押す（公開しないと他の利用者には反映されない）
3. 通常URLで**保存が通ること**を確認（操作バーが画面下部なら新版）
4. 未完成の届（`CtnNotifications` の項目 21〜28、46）を削除
   ※ 以前のバグで作られた中途半端なデータ。修正版では発生しない

## ライブラリ配信について（IT 向け補足）

`includeClientSideAssets: false` + `cdnBasePath` を使い、JS をパッケージに同梱せず
サイト内のドキュメントライブラリから配信している。SPFx の標準機能。

**目的**: コード修正のたびにアプリカタログへの再登録（＝IT 依頼）が発生するのを避けるため。
マニフェストを変える変更（Web パーツの追加・名称変更・プロパティ既定値・配置許可・
API 権限要求）だけが引き続き再登録の対象になる。

**配信元**: 同一テナント内の
`/sites/ClinicalTrialSubmissionAssistant-Demo/ClientSideAssets`
外部 CDN やテナント外への通信は無い。

## 1.6.0.0 に入っている修正（参考）

デプロイ済みの `1.0.0.0` から、以下が入っている。実テナントで踏んだ不具合が中心。

### 書き込みができなかった原因の修正（最重要）

SPFx の `SPHttpClient` は OData v4 を使うため、etag は応答の `@odata.etag`
（アットマーク付き）に載る。実装が `odata.etag`（@ なし）を読んでいたため etag が常に
未取得となり、`IF-MATCH` を使う**すべての更新が失敗**していた。保存・届の作成・承認が
動かなかったのはこれが単一の原因。

### ロール別の権限制御（1.6.0.0 で追加）

4ロール（起票・レビュー・承認・薬事）の「できる／できない」を実装した。これまでは定義だけが
あり、操作バーはステータスのみで出し分けていたため、起票担当でも承認でき、誰でも提出できた。

| 操作 | 必要な権限 |
| --- | --- |
| 起票・編集・レビュー送付・削除 | 起票担当以上 |
| 差し戻し | レビュー担当以上 |
| 承認 | 承認者以上 |
| 提出・マスタ設定の変更 | 薬事担当のみ |
| 閲覧・XML出力 | 制限なし |

ロールは SharePoint サイトグループ（CTN 起票担当 / レビュー担当 / 承認者 / 薬事担当）の
所属から解決する。**どのグループにも属さない利用者は閲覧のみ**になる。

### 差し戻し機能（1.6.0.0 で追加）

レビュー中の届を作成中へ戻せるようにした。理由の入力を必須とし、起票者の画面と監査ログに
残す。従来はステータスが一方向で、レビュー担当に操作が無かった。

### その他の修正

- 失敗が画面に出ず「押しても無反応」に見えていた問題（保存・作成・レビュー送付・
  取り込み・XML生成に例外処理が無かった）
- 読み込み失敗時に「読み込み中…」のまま固まる問題
- 1行テキスト列の 255 文字超過で書き込みが失敗する問題
- 作成の2段目が失敗すると中途半端な届が残り、再試行のたびに増える問題
- 壊れたデータが1件あると全画面が開けなくなる問題
- 監査ログの追記失敗が業務操作を失敗扱いにする問題

### UI 改善

- 操作バー（保存・レビュー送付など）を画面下部に固定
- 「施設を追加」で追加されたカードへ自動スクロール
- 全幅列セクションへの配置に対応（`supportsFullBleed`）
- Web パーツの高さを画面に合わせるオプション

### 機能追加

- 初期セットアップ画面（ボタン1つでリストとロール用グループを作成。
  これにより PowerShell や Entra ID アプリ登録の依頼が不要になった）
- データソース切替の即時反映

### 性能

保存1回あたりの SharePoint への往復を 7 回から 3 回へ削減（etag の引き継ぎ、治験成分記号の
キャッシュ、採番不要時のシリーズ取得の省略、更新後の再取得の省略）。

### 検証

テスト 240 件パス（demo/app 94 + ctn-spfx 146）、`gulp bundle` / `package` がエラー0・警告0。
