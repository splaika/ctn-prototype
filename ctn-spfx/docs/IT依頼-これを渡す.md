## ライブラリ配信について（IT 向け補足）

`includeClientSideAssets: false` + `cdnBasePath` を使い、JS をパッケージに同梱せず
サイト内のドキュメントライブラリから配信しています。SPFx の標準機能です。

**目的**: コード修正のたびにアプリカタログへの再登録（＝IT 依頼）が発生するのを
避けるため。マニフェストを変える変更（Web パーツの追加・名称変更・プロパティ既定値・
配置許可・API 権限要求）だけが引き続き再登録の対象になります。

**配信元**: 同一テナント内の
`/sites/ClinicalTrialSubmissionAssistant-Demo/ClientSideAssets`
外部 CDN やテナント外への通信はありません。

## 1.6.0.0 に入っている修正（参考）

デプロイ済みの `1.0.0.0` から、以下が入っています。実テナントで踏んだ不具合が中心です。

**書き込みができなかった原因の修正（最重要）**

SPFx の `SPHttpClient` は OData v4 を使うため、etag は応答の `@odata.etag`
（アットマーク付き）に載ります。実装が `odata.etag`（@ なし）を読んでいたため
etag が常に未取得となり、`IF-MATCH` を使う**すべての更新が失敗**していました。
保存・届の作成・承認が動かなかったのはこれが単一の原因です。

**ロール別の権限制御（1.6.0.0 で追加）**

4ロール（起票・レビュー・承認・薬事）の「できる／できない」を実装しました。
これまでは定義だけがあり、操作バーはステータスのみで出し分けていたため、
起票担当でも承認でき、誰でも提出できる状態でした。

| 操作 | 必要な権限 |
| --- | --- |
| 起票・編集・レビュー送付・削除 | 起票担当以上 |
| 差し戻し | レビュー担当以上 |
| 承認 | 承認者以上 |
| 提出・マスタ設定の変更 | 薬事担当のみ |
| 閲覧・XML出力 | 制限なし |

ロールは SharePoint サイトグループ（CTN 起票担当 / レビュー担当 / 承認者 / 薬事担当）
の所属から解決します。**どのグループにも属さない利用者は閲覧のみ**になります。

**差し戻し機能（1.6.0.0 で追加）**

レビュー中の届を作成中へ戻せるようにしました。理由の入力を必須とし、起票者の画面と
監査ログに残します。従来はステータスが一方向で、レビュー担当に操作がありませんでした。

**その他の修正**

- 失敗が画面に出ず「押しても無反応」に見えていた問題（保存・作成・レビュー送付・
  取り込み・XML生成に例外処理が無かった）
- 読み込み失敗時に「読み込み中…」のまま固まる問題
- 1行テキスト列の 255 文字超過で書き込みが失敗する問題
- 作成の2段目が失敗すると中途半端な届が残り、再試行のたびに増える問題
- 壊れたデータが1件あると全画面が開けなくなる問題
- 監査ログの追記失敗が業務操作を失敗扱いにする問題

**UI 改善**

- 操作バー（保存・レビュー送付など）を画面下部に固定
- 「施設を追加」で追加されたカードへ自動スクロール
- 全幅列セクションへの配置に対応（`supportsFullBleed`）

**機能追加**

- 初期セットアップ画面（ボタン1つでリストとロール用グループを作成。
  これにより PowerShell や Entra ID アプリ登録の依頼が不要になりました）
- データソース切替の即時反映

**性能**

保存1回あたりの SharePoint への往復を 7 回から 3 回へ削減
（etag の引き継ぎ、治験成分記号のキャッシュ、採番不要時のシリーズ取得の省略、
更新後の再取得の省略）。
