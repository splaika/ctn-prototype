## 2. 実テナントで踏んだ不具合の根本原因（最重要）

**SPFx の `SPHttpClient` は OData v4 を既定で使い、`OData-Version: 4.0` を自動で付ける。**
v4 の最小メタデータでは etag は **`@odata.etag`（アットマーク付き）** に載るが、実装は
`odata.etag`（@ なし）を読んでいた。そのため etag が常に未取得となり、`IF-MATCH` を使う
**すべての更新が失敗**していた。保存・届の作成・承認が動かなかったのは、これ一つが原因。

派生して以下も v3 記法で誤っていた（修正済み）。

- `Accept: application/json;odata=minimalmetadata` → v4 では `odata.metadata=minimal`（ドット）
- プロビジョニングの `__metadata` → v4 では `@odata.type`
- `Content-Type: application/json;odata=verbose` → v4 では `odata.metadata=none`

**項目の追加・更新の `Content-Type` は v3 記法のまま意図的に残している。** 本文が素の JSON で
SharePoint が見ておらず、実テナントで成功を確認済み。仕様準拠のために動いている経路を
根拠なく変えない判断。コード内にもコメントあり。

### なぜテストで気付けなかったか

**当時のテスト109件はすべて `ISpRestClient` を差し替えており、HTTP と応答解析の層を
一度も通っていなかった。** テストは「想像した SharePoint」を検証しており、想像が外れた
箇所は全てすり抜けた。`src/data/spClient.test.ts`（25件）でこの層を埋めた。

同じ理屈で、`provision/browser-setup.js`（素の fetch）が動いたのも整合する。
素の fetch は `OData-Version` を送らないため、サーバーが v3 とみなし v3 記法が通る。

## 3. 踏んだ落とし穴（同じことを繰り返さないために）

**`release/` に古いバンドルが蓄積し、パッケージに全部入る**
`gulp clean` + `release/ dist/ temp/ lib/ sharepoint/` の削除をしてから
`npm run package` すること。放置すると `.sppkg` が 327KB → 3.4MB に膨らみ、
最悪はマニフェストが古いバンドルを指して「デプロイしたのに直っていない」になる。
**パッケージを渡す前に必ず中身を検証すること**（手順は下の 6 章）。

**`solution.version` を固定したままにすると、どの版が動いているか判別できない**
これで半日を失った。**リリースのたびに必ず上げる。**
アプリカタログの「アプリのバージョン」列で確認できる。

**`npm run sync` を実行すると `gulp serve` が `EPERM: watch` で落ちる**
`src/shared/` を作り直すため。共有コードを直したら、同期のあとにサーバーを再起動する。

**デバッグURLで `F5` を押すとクエリ文字列が落ちて旧版に戻る**
リロードではなく URL を開き直す。**判別の目印: 操作バーが画面下部にあれば新版、
上部にあれば旧版（1.0.0.0）。**

**`.sppkg` を ZIP に包んで渡すと、ZIP 自体がアップロードされて失敗する**
実際に起きた。Teams か SharePoint でファイルを直接渡す。

## 8. 設計上の判断（変えるときは理由を確認すること）

- **届は集約JSON（`CtnPayload`）+ 昇格列を同一書き込みで更新。** 子配列を別リストに
  分けない。SharePoint にリスト横断トランザクションが無いため
- **`IF-MATCH: *` は使わない。** 実 etag のみ。提出時の採番確定は
  再取得→再計算→412リトライ
- **ロールは SharePoint サイトグループから解決。** 権限管理を SharePoint 側へ寄せ、
  サイト所有者権限で運用できるようにするため
- **リスト定義の単一ソースは `provision/ctn-lists.schema.json`。**
  対応表・PowerShell・ブラウザ用スクリプト・リポジトリの列名がすべてここから導かれる
- **採番ロジックの単一ソースは `demo/app/src/ctn/logic.ts`。**
  SPFx 側で再実装しない
- **性能**: 保存1回あたりの往復を 7 → 3 に削減（etagの引き継ぎ、治験成分記号の
  キャッシュ、採番不要時のシリーズ取得の省略、更新後の再取得の廃止）
